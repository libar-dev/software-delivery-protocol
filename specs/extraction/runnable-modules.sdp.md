# Derived runnable modules freeze the registrar interface

## Intent
- problem: A bound example test would otherwise repeat registration, step dispatch and oracle comparison that the graph and contracts already determine.
- outcome: Give each bindable example a generated registrar, so its authored test keeps semantics derivation cannot supply.
- value: A Spec and a small authored semantics module express the test while the engine neither loads nor executes adopter code.

## Behavior
- rule: Code generation emits a registrar called with `createWorld`, `invoke`, `observe`, `expected` and optional `assertions`. It owns describe/it registration, step dispatch, the three-way comparator and failure rendering. The authored test keeps its top-level `specTest` anchor and one activation call beside its semantics. The authored file imports the generated registrar; the generated module imports no authored code. Normal runner discovery loads the authored file and activates registration. Generated modules never self-register; the graph records binding, never liveness.
- rule: Generated sibling path — for each bindable example, codegen emits exactly one generated registration module as a sibling `*.generated.ts` of the authored `.test.ts` (deterministic filename keyed by Spec ID, not by the authored suite filename). One authored suite may verify many examples without their registrar map keys or output paths colliding. Exactly one generated registration per example; a second registration path for the same example is refused. Generated siblings are disposable build output: an adopted registrar is committed because authored code imports it, while unadopted registrars remain ignored, regenerable output and confer no migration claim.
- rule: `generated/registrars.json` is a versioned, sorted manifest of every extraction-root-relative registrar sibling owed by the build. Publication reconciles the manifest and removes siblings no longer owed under the build-pipeline law. `--check-clean` compares the manifest and every sibling byte with fresh generation. Preflight independently compares every tracked adopted registrar in the worktree and Git index with regenerated bytes.
- rule: Registration-path loudness — multiple anchors in one authored suite still locate one registrar sibling; when one example resolves to more than one distinct authored suite path, generation emits a named finding and withholds that registrar rather than selecting a path silently.
- rule: Generated registrars import shared runtime helpers from `@libar-dev/software-delivery-protocol/testing` and types through public package subpaths. Public exports are the root for model, anchors and public types, `./anchors` for zero-dependency anchor builders, `./runner` for the framework-neutral plan/run core, `./vitest` for `bindExample`, and `./testing` for the registrar runtime. Authored suites may import anchor builders through the root or `./anchors`. Authored and generated modules never import private `src` paths. The supported optional Vitest peer range is `>=2`, as declared by the package.
- rule: Step identity is the step's contract key: its step key under `spec:carrier.step-keys`, or its skeleton text when it has none, and generation introduces no ordinal or slug identity. A directly authored `bindExample` handler map fails the typecheck when one of its keys goes stale. An adopted registrar holds no authored per-step handler: a stale committed registrar fails the regeneration preflight, and its internal handlers change with the contract when it is regenerated. The contract key of a Then step of the example space also names an Outcome `kind`, so changing it fails the typecheck of an authored oracle that names the old kind.
- rule: Handler resolution — the generated registrar's internal dispatch object is an exhaustive mapped type over the contract's step keys: removing or staling one of those generated callbacks is a `tsc` error naming that step. The adopted authored surface retains no per-step callbacks (and therefore no step keys); its five adapters are required keys (`assertions` optional), so a missing or stale authored callback is a `tsc` error naming that adapter. These are the two exhaustive mapped-type checks; demanding an authored error name a step while simultaneously retaining no authored per-step surface is refused as contradictory. Codegen cannot statically see authored handlers, so no generation-time handler refusal is promised — the type system carries it. Existing generation-time refusals (unbindable example, incompatible vocabulary, colliding path) are reused unchanged.
- rule: Scenario-level invocation — the five-adapter interface carries one product `invoke` per example, so the first `When` occurrence invokes it and later `When` occurrences in the same lawful scenario do not repeat side effects.
- rule: At the first Then, the comparator refuses an incomplete point before calling the oracle and otherwise evaluates and caches `expected(point)`. It finds the authored Then whose contract key equals `expected.kind`, compares that step's authored parameters with the oracle payload, reads `observe(world)`, compares observed and oracle outcomes, and runs additional assertions separately. Actual-equals-oracle alone is insufficient: a Spec parameter mutation must fail. The oracle accepts `Partial<Conditions>`; the registrar never casts a partial point to Conditions.
- rule: Oracle payload versus Spec Then parameters and observed versus oracle outcomes use deep structural equality on the authored shape. Diagnostics name missing, extra or changed values by path and show expected and actual values. The comparator quotes authored Then parameters and skeleton text without rephrasing them.
- rule: Failure rendering reuses the contract's matching Then step plus the existing `renderContractStep` path. When the oracle selected no authored Then, emit a scenario-level diagnostic quoting Spec ID, oracle kind, and the contract keys of the available Then steps; preserve the original assertion as `cause`.
- rule: Bound unspecified outcome — `unspecified` names a coverage gap in the example space, but a bound executable example selecting it reddens because no authored Then may silently witness that gap.
- rule: The authored top-level `specTest` carries a non-empty `verifies` target naming the example. It remains the source of `has-verifier`; generated execution confers no delivery fact and records no pass state.
- rule: Additive assertions — optional `assertions` may add domain checks the Outcome union cannot express; they never replace steps (3) or (5) of the three-way comparator and never silence a Spec-param or oracle mismatch.
- rule: Case mapping and outlines — outline rows map one deterministic case per row in carrier order when a multi-row table sugar expands statically into sibling examples (point-per-example). Scenario Outlines and inline Examples tables stay refused as executable carrier constructs inside a single example; one example remains one point and earns exactly one generated registration.
- rule: Registrars use no environment, global or module side channel, mutable global registry or singleton world shared across examples. Generated siblings export the registrar and never self-register. Generation derives no domain observation; the engine never loads or executes adopter code. Registrars do not become generated test harnesses. Scenario Outlines stay refused. The interface changes neither the claim taxonomy, anchor bindings nor the contract-key identity of steps.

## Design
- registrar: `export declare function registerExample<World>(adapters: RunnableExampleAdapters<World, Conditions, Outcome>): void;` is the signature template; substitute the generated function name and the parent's generated Conditions and Outcome names.
- registrarName: Prefix `register` to the example's final dot-delimited id segment in PascalCase after removing the first occurrence of the parent's final segment in PascalCase; if removal leaves an empty name, use the example's PascalCase segment. PascalCase splits that segment at non-alphanumeric characters, capitalizes each part, and prefixes `X` when the result starts with a digit.
- adapters: `interface RunnableExampleAdapters<W, C, O extends { readonly kind: string }> { readonly createWorld: (point: Partial<C>) => W; readonly invoke: (world: W, point: Partial<C>) => void | Promise<void>; readonly observe: (world: W) => O; readonly expected: (point: Partial<C>) => O; readonly assertions?: (world: W, observed: O) => void | Promise<void>; }`
- registrarPath: The authored suite directory plus the example id without the `spec:` prefix and the suffix `.test.generated.ts`, retaining the id's dots.
- registrarManifest: `generated/registrars.json` carries the versioned, sorted extraction-root-relative registrar paths owed by the build.
- thenBinding: `compareContractOutcome(execution, { kind: "then", key, text, params })` is the generated binding of a Then step; it compares only the step whose `key` equals the oracle's `kind`.
- noMatchingThen: `scenario <spec>: oracle selected "<kind>"; available Then steps: "<key>", …` is the diagnostic when no authored Then matches, listing each Then step's contract key in contract order, with the original assertion as `cause`.
