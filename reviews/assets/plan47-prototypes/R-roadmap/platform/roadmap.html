  • non-blocking · spec:context.journal#question.baselineMigrationContract

    Extension E-25: the doc says a migration writes a baseline event holding the migrated state and that rebuild starts from the latest baseline, and it does not say who computes that state, who drives the migration, or what a live command does on a stream the migration has not reached; this Spec fixes the representation, an event of the reserved type baseline whose payload holds the state and its schema version and is bounded by the stream's budgetBytes instead of the payload bound, a baselineVersion on the stream row, a BaselineMigration registered on the stream type whose migrate function computes the migrated state from the saved state, or, for a step that declares readsHistory, from the saved state and the events since the last baseline in the sweep only, the rule that stateSchemaVersion counts meaning only and lives on the registration, one helper migrateToSchemaVersion that writes the baseline chain, called by the adapter on load for a chain that reads no history and by the writeBaseline maintenance mutation for every chain, the code-older-than-data error, the writeBaseline mutation built by defineMaintenance and declared with the component's public mutation builder, the parent-side scheduled chain that drives it by cursor, the batch bound derived from budgetBytes, the upcasting rule for old event schema versions, the fold bound of 500 events with the refusals rebuildStream returns above it and for a stream awaiting its baseline, the retirement rule for a migration, and the payload byte check in append;
