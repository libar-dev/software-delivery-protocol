## Execution strategy
### Parallel execution waves
> Target 5-8 todos per wave. Fewer than 3 (except the final) means you under-split.

- **Wave 0 — rulings + independent starts (todos 1–4, all parallel):** commissioning hygiene (incl. the already-decided E2 placement ruling text); G convention ruling (binding table); E1 bridge recipe; F tracer family.
- **Wave 1 — engines (todos 5–11):** G anchor authoring (blocked by todo 2) ∥ E2 `sdp new spec` ∥ E2 `validate --watch` ∥ F families anchors / slot-notation / duplicate-ids / kind-evidence (each blocked by todo 4's tracer).
- **Wave 2 — consume + close (todos 12–15):** E1 census/fan-in + projection-verb recipes (blocked by todo 5's rows) ∥ E3 amendment attempt ∥ H decide/defer (wants todo 12's evidence) ∥ on-ramp prose pass (blocked by 3, 6, 7, 12).
- **Wave 3 — arc close (todos 16–18, sequential):** close record with re-derived measurements → plan-32-mold independent review → final gate + status flips.

**Wave-gate rule (binding on the orchestrator).** Within a wave, todos verify with lane-safe focused commands only (`npx vitest run <file>`, `npm run --silent sdp -- validate`, `sdp:q` bodies). Every command that writes `generated/` or spans the whole tree — `generate:self-hosting`, `check:self-hosting`, `check:example`, `preflight`, full `npm run check` — is SERIALIZED: one runner at a time, scheduled by Atlas, with the full `npm run check` run once at each wave boundary after the wave's streams merge. Parallel streams never regenerate projections concurrently (plan-32's merge-blocking fragility was exactly this race). Worktree-per-stream remains Atlas's option for harder isolation; the default is one worktree plus this rule. Every per-todo acceptance line naming `npm run check`, `generate:*`, `check:*`, or `preflight` is executed under this serialization — never concurrently with another stream's such command.
