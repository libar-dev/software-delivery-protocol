# arc-keystone-engines - Work Plan

## TL;DR (For humans)

**What you'll get:** Four of the five commissioned next-arc work items delivered as one plan: a binding decision on which kinds of truth the Gherkin format can honestly hold, tests that write their own plumbing so authors only supply meaning, two new generated views of the whole corpus (a census page and diagrams), and a small honest way for code to declare what component it belongs to and what it uses. The fifth item (the agent command surface) deliberately waits, because it should consume what this plan builds.

**Why this approach:** The two decision sessions run first and in parallel so no code work guesses at their outcomes; the highest-payoff engine work (generated test plumbing) is gated behind a frozen interface because planning found the one arc-sinking risk — there is no stable identity linking a spec's words to the author's code, so that link is designed before anything is generated.

**What it will NOT do:** It will not touch the agent command surface, reopen the settled file-format suffix, let prose execute itself, or let any generated artifact become a second source of truth.

**Effort:** XL
**Risk:** Medium - two of the four items are judgment sessions whose honest outcome may be "refused"; the plan treats refusal as success, which can shrink the visible deliverables.
**Decisions to sanity-check:** Gherkin likely stays honest only for behavior/example kinds (universality becomes a generated *view*, not a format flip); `implements` is likely declined in favor of the existing `satisfies`; the census page ships before diagrams.

Your next move: start work (`/start-work arc-keystone-engines`). Full execution detail follows below.

## Execution strategy
Three waves; no OTHER brief serializes behind the A ruling — only A's own follow-through (todo 9) is gated on it. Ruling sessions (todos 2, 3) are design work whose deliverable is a decision Spec — each enumerates its exact questions, the evidence, and the lawful outcome set (refusal is a lawful outcome); gated follow-through todos name per-branch actions so the executor makes zero judgment calls. Parallel-worker discipline per repo AGENTS.md: one batched dispatch of all dependency-free units, ≥3 workers when available, atomic units each owning one deliverable + one verification command. Historical evidence (gen-1 `architect/` checkout paths, git SHAs) is provenance for rulings, never an execution input — executors must not need to open those trees.
