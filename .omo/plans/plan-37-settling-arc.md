## Execution strategy
### Parallel execution waves
> Target 5-8 todos per wave. Fewer than 3 (except the final) means you under-split.

- **Wave 0 — commission + tracer + preflights (todos 1–4, all parallel):** commissioning hygiene; I-0 tracer (adopt beside existing registrars — the new lesson); J recipe-9 preflight + evidence-packet template (read-only); K measurement definition frozen + census scripts built (validated against plan-35-era sessions, NOT the verdict corpus).
- **Wave 1 — heavy I lanes + first J families (todos 5–11):** I-1 validators ∥ I-2 Gherkin (own tranche, refuse candidate) ∥ I-5 tails (pack-markdown ∥ consumers ∥ sdp-import) ∥ J-model ∥ J-extraction (evidence packets + prepared diffs, unapplied).
- **Wave 2 — remaining I + remaining J (todos 12–15):** I-3 projections ∥ I-4 extraction ∥ J-consumers ∥ J-carrier. Then the W2 merge gate.
- **Ratification checkpoint (between W2 and W3):** the eight J evidence packets + prepared diffs presented in ONE batch; the owner ratifies or refuses per Spec. Todo 16 applies only ratified rungs.
- **Wave 3 — measure, then close (todos 16–20, sequential after 16):** apply ratified readiness → K gather + verdict → close record with re-derived measurements → plan-32-mold independent review → final gate + status flips.

**Wave-gate rule (binding on the orchestrator), extended.** Within a wave, todos verify with lane-safe focused commands only (`npx vitest run <file>`, `npm run --silent sdp -- validate`, `sdp:q` bodies). Every command that writes `generated/` or spans the whole tree is SERIALIZED, one runner at a time, scheduled by Atlas — and this arc names **`sdp build` / registrar regeneration explicitly** in the serialized set (plan 35 named only `generate:self-hosting`; the registrar emitter is `src/cli/build-command.ts`), alongside `generate:self-hosting`, `check:self-hosting`, `check:example`, `preflight`, and full `npm run check`. The full gate runs once at each wave boundary after the wave's streams merge. Adoption activation (regen → force-add → byte gate) is a queued service: an I lane finishes adapters, requests regen, next lane runs. One worktree plus this rule is the default; worktrees do NOT dodge it (tracked force-adds still collide at merge). Every per-todo acceptance line naming a serialized command is executed under this rule — never concurrently with another stream's such command.
